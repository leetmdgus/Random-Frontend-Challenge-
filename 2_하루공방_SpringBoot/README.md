# 🏺 하루공방 — 동네 공방 원데이 클래스 예약

> **Week 2 · 핵심 학습: Spring Boot 기초**
> Controller · Service · Repository 계층 · Spring Data JPA 1:N 연관관계 · Bean Validation
> · 전역 예외 처리(`@RestControllerAdvice`) · `@Transactional` 과 비즈니스 규칙

## 서비스 소개

도자기, 목공, 향초, 가죽, 드로잉 같은 **동네 공방의 원데이 클래스**를 둘러보고 예약하는 서비스입니다.

- **수강생**은 클래스 목록에서 남은 자리를 확인하고, 이름 · 휴대폰 번호 · 인원만으로 예약합니다.
  예약하면 **예약 코드**(예: `HR-K7P2Q`)를 받고, 코드 + 전화번호로 예약을 확인하거나 취소합니다.
- **호스트(공방)** 는 날짜가 정해진 클래스를 열고, 클래스별 **예약자 명단**을 봅니다.

로그인은 없습니다. (인증은 이번 주 범위가 아닙니다.) 결제도 없고 현장 결제로 안내합니다.

이번 주의 핵심은 **"클래스 하나에 예약 여러 개"** 관계와,
**"정원을 넘겨 예약되면 안 된다"** 같은 규칙을 서버에서 지키는 것입니다.

## 규칙 (서버가 지켜야 하는 것)

화면은 **일부러 입력값과 규칙을 거의 검사하지 않습니다.**
마감된 클래스에도 예약 폼이 보이고, 취소된 예약에도 취소 버튼이 보입니다. **서버가 막아야 합니다.**
Mock 은 아래 규칙대로 동작합니다.

### 입력값 검증

| 대상 | 항목 | 규칙 |
| --- | --- | --- |
| 클래스 | 이름 | 앞뒤 공백 제외 2~40자 |
| | 카테고리 | 5개 중 하나 |
| | 호스트 이름 | 1~20자 |
| | 장소 | 1~60자 |
| | 시작 일시 | 필수, **지금 이후** |
| | 진행 시간 | 30~480분, 정수 |
| | 가격 | 0~1,000,000원, 정수 (0 = 무료) |
| | 정원 | 1~30명, 정수 |
| | 소개 | 0~1000자 |
| 예약 | 이름 | 1~20자 |
| | 휴대폰 번호 | `010-1234-5678` 또는 `01012345678` 형식. 저장 · 비교는 한 가지 형식으로 |
| | 인원 | 1~4명, 정수 |
| | 요청사항 | 0~200자, 비우면 "없음" |

빈 숫자 칸은 `null` 로 전송됩니다.

### 비즈니스 규칙

| # | 상황 | 결과 |
| --- | --- | --- |
| R1 | 이미 시작했거나 끝난 클래스에 예약 | 거절 — "이미 시작했거나 끝난 클래스는 예약할 수 없어요." |
| R2 | 신청 인원 > 남은 자리 | 거절 — "남은 자리가 N석뿐이에요." / 0석이면 "자리가 모두 찼어요." |
| R3 | 같은 클래스에 같은 휴대폰 번호로 **확정된** 예약이 이미 있음 | 거절 (취소한 예약은 제외) |
| R4 | 예약 코드는 서버가 만들고, 겹치지 않는다 | |
| R5 | 남은 자리 = 정원 − **확정된** 예약들의 인원 합계 | 취소된 예약은 세지 않는다 |
| R6 | 코드 + 전화번호가 둘 다 맞아야 조회 · 취소 가능 | 하나라도 다르면 "찾을 수 없음" |
| R7 | 이미 취소된 예약을 다시 취소 | 거절 |
| R8 | 시작한 클래스의 예약을 취소 | 거절 |
| R9 | 취소는 삭제가 아니다 | 상태가 "취소됨"으로 바뀌고 취소 시각이 남는다. 명단에도 계속 보인다 |

> 💡 **동시성 실험**: 남은 자리가 1석인 클래스에 두 브라우저에서 거의 동시에 예약을 눌러 보세요.
> 둘 다 성공한다면 R2 가 동시 요청에서 깨진 것입니다.

## 화면별 동작 설명

### 1. 클래스 목록 — `/`

- 들어오면 클래스 목록을 불러옵니다. **시작 일시가 빠른 순서**로 보여 줍니다. (페이지 나누기 없음)
- 카테고리 칩 · "예약 가능한 클래스만" 토글을 바꾸면 다시 불러옵니다. 조건은 주소창에 남습니다.
  (예: `/?category=WOOD&available=true`)
- 카드: 카테고리 · 호스트, 이름, 일시, 장소, 가격(0원이면 "무료"), 남은 자리 막대.
  자리가 없으면 "마감", 시작 시간이 지났으면 "지난 클래스" 표시가 붙고 흐려집니다.
  → 목록 응답의 클래스마다 **확정 예약 인원 합계**(`reservedCount`)가 있어야 합니다.

### 2. 클래스 상세 · 예약 — `/workshops/{id}`

- 클래스 하나를 불러옵니다. 없는 id면 "이 클래스는 찾을 수 없어요" 화면.
- 오른쪽 예약 패널: 상태 배지, 남은 자리, 예약 폼.
  - 인원은 −/+ 버튼으로 바꿉니다. 화면은 1~4 범위를 막지 않습니다. (0명, 5명도 전송됨)
  - 합계 금액 = 가격 × 인원 (화면에서 계산, 안내용)
- **예약 성공** → 폼 자리에 **예약 코드**, 예약자 · 연락처 · 인원 · 결제 예정 금액이 나옵니다.
  남은 자리를 다시 불러와 갱신합니다. "내 예약 보기"를 누르면 코드가 채워진 채 내 예약 화면으로 갑니다.
  → 예약 응답에는 서버가 만든 `code` 가 있어야 하고, 전화번호는 서버가 정리한 형식으로 돌아옵니다.
- **입력값 오류** → 각 입력칸 아래에 메시지 (`name`, `phone`, `headcount`, `memo`)
- **규칙 위반 (R1~R3)** → 폼 아래에 상태 코드와 서버 메시지를 그대로 보여 줍니다.
- 아래쪽 "예약자 명단 보기" 링크로 호스트 화면에 갈 수 있습니다.

### 3. 내 예약 — `/my`

- 예약 코드와 휴대폰 번호를 입력하고 "예약 찾기".
  예약 완료 화면에서 넘어오면 코드는 미리 채워져 있습니다. (전화번호는 주소에 넣지 않습니다)
- 찾으면 티켓 모양 카드로 **클래스 정보와 예약 정보를 함께** 보여 줍니다.
  → 조회 응답에는 예약 + 그 예약의 **클래스 정보**가 함께 있어야 합니다.
- 못 찾으면 (R6) 404 메시지를 보여 줍니다.
- **예약 취소** → 확인 창 → 성공하면 카드가 "취소됨"으로 바뀌고 취소 시각이 나옵니다.
  실패(R7, R8)하면 서버 메시지를 보여 줍니다.

### 4. 클래스 열기 (호스트) — `/host/new`

- 폼을 채워 "클래스 열기" → 성공하면 그 클래스의 예약자 명단 화면으로 이동합니다.
  → 등록 응답에 새 클래스의 `id` 가 있어야 합니다.
- 검증 실패 → 각 입력칸 아래에 메시지
  (`title`, `category`, `hostName`, `place`, `startsAt`, `durationMinutes`, `price`, `capacity`, `description`)
- 시작 일시는 `YYYY-MM-DDTHH:mm` (초 · 시간대 없음, 한국 시간)으로 보냅니다.

### 5. 예약자 명단 (호스트) — `/host/workshops/{id}`

- 클래스 정보와 예약 목록을 **함께** 불러옵니다. 없는 클래스면 404 화면.
- 요약: 확정 예약 건수 · 참여 인원 / 정원 · 예상 매출 (화면에서 계산)
- 표: 번호, 예약자 + 코드, 연락처, 인원, 요청사항, 상태, 신청 시각. **신청 순서대로**, 취소된 예약은 흐리게.

> 💡 클래스 목록에서 클래스마다 예약 인원을 따로 세고 있지는 않은지, 실행되는 SQL 로그를 확인해 보세요. (N+1)

화면은 `frontend/src/api/` 의 함수 7개만 호출합니다. 각 함수의 `TODO(백엔드 연결)` 를 채우세요.
**URL, HTTP 메서드, 상태 코드, 요청/응답 형식, 엔티티 설계는 직접 정하세요.**

| 함수 | 쓰는 화면 | 받는 값 | 돌려줘야 하는 값 |
| --- | --- | --- | --- |
| `fetchWorkshops(query)` | 목록 | 카테고리, 예약 가능한 것만 여부 | `Workshop[]` (시작 일시 순) |

| `fetchWorkshopReservations(id)` | 명단 | 클래스 id | `Reservation[]` (신청 순) / 없으면 404 |

[`reservations.ts`](frontend/src/api/reservations.ts)

| 함수 | 쓰는 화면 | 받는 값 | 돌려줘야 하는 값 |
| --- | --- | --- | --- |
| `createReservation(workshopId, input)` | 상세 | 클래스 id, `ReservationInput` | 확정된 `Reservation` |
| `fetchMyReservation(code, phone)` | 내 예약 | 코드, 전화번호 | `ReservationDetail` (예약 + 클래스) / 없으면 404 |
| `cancelMyReservation(code, phone)` | 내 예약 | 코드, 전화번호 | 취소된 `ReservationDetail` |

- 화면용 타입: [`frontend/src/types.ts`](frontend/src/types.ts). 서버 응답이 다르면 `api/` 에서 변환하세요.
- [`frontend/src/api/client.ts`](frontend/src/api/client.ts) 의 `request()` 를 쓰면 에러 응답이 자동으로 `ApiError` 로 바뀝니다.
  에러 응답 형식은 직접 정하세요. `toApiError()` 가 이해하는 형식:
  - 메시지: `message` / `detail` (ProblemDetail) / `error`
  - 필드 에러: `errors` 또는 `fieldErrors` — `[{ "field": "...", "message": "..." }]` 배열이나 `{ "필드": "메시지" }` 객체
  - 다른 형식으로 정했다면 이 함수만 고치면 됩니다.
- **404 는 "찾을 수 없음" 화면**으로, 나머지 에러는 상태 코드 + 메시지로 보여 줍니다.
  규칙 위반(R1~R3, R7, R8)과 입력값 오류에 어떤 상태 코드를 쓸지 정해 보세요.
- Mock 구현: [`frontend/src/mock/store.ts`](frontend/src/mock/store.ts) — 서버의 "기대 동작" 참고용.
